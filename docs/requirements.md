# FamilyHub MVP — Техническое задание (v0)

## 0. Цель приложения

FamilyHub — это семейный органайзер.

Он решает 3 реальные боли:

1. Никто ничего не делает вовремя → нужно распределять задачи по людям и видеть, кто ответственный.
2. Покупки забываются → нужен общий список покупок.
3. Постоянные ссоры "я делаю всё один" → нужен честный учёт вклада через баллы.

Эта версия (MVP) не пытается быть идеальной. Она должна работать в живой семье сразу после установки.

## 1. Навигация и экраны MVP

Bottom navigation (4 вкладки):

1. **Дом**
2. **Задачи**
3. **Покупки**
4. **Рейтинг**

Пока всё. Календарь и цели не выносим в отдельные экраны — календарь встраивается в Дом как виджет ближайших событий.

### 1.1. Экран "Дом"

Показывает общую картину на сегодня.

Блоки на экране:

* "Мои задачи сегодня"

  * список из актуальных невыполненных задач, назначенных на текущего пользователя
  * максимум 3-5 штук
* "Ближайшие события семьи"

  * список на ближайшие 2 календарных события (семейных), по дате
* "Мои баллы за эту неделю"

  * целое число

Действия пользователя на этом экране:

* тап по задаче → можно отметить "сделано"
* кнопка "все задачи" → ведёт на экран Задачи
* (на будущее) кнопка "добавить событие" — не обязательна в v0, но можно сразу предусмотреть FAB.

### 1.2. Экран "Задачи"

Верхние вкладки (TabRow):

* "Мои"
* "Все"

Список задач в каждой вкладке — вертикальный LazyColumn.

Элемент задачи показывает:

* чекбокс статуса (todo / done)
* текст задачи (title)
* подзаголовок мелким текстом:

  * кому назначено
  * кто создал
  * дедлайн (если есть)
  * повторяемость (если есть)

В правом верхнем углу:

* кнопка [+] создать задачу.

Экран создания задачи (диалог или отдельный экран):

* Ввод названия (обязательно)
* Описание (опционально)
* Выполнить до (дата или "сегодня")
* Повторение (нет / каждый день / каждую неделю)
* Кому назначить (выбор из списка членов семьи)
* Создать

После создания задача получает статус `todo`.

Логика статусов:

* Пользователь может переключить задачу todo ↔ done.
* Когда задача "done":

  * Исполнитель получает баллы.
  * Если задача была повторяющейся → создаётся новая копия на следующий день / неделю (см. раздел логики ниже).

### 1.3. Экран "Покупки"

Очень простой экран списка покупок.

Компоненты:

* Список пунктов (LazyColumn).

  * чекбокс "уже куплено"
  * текст ("молоко 2.5%")
  * подпись мелким текстом: кто добавил.

FAB [+]:

* Добавить позицию:

  * Текст товара (обязательно)
  * Кнопка "Сохранить"
  * После сохранения товар появляется в общем списке со статусом isBought = false.

Никаких категорий, приоритетов и т.д. в MVP не делаем.

Чекбокс "куплено" просто меняет isBought = true/false.

### 1.4. Экран "Рейтинг"

Цель — показать вклад каждого участника семьи за текущую неделю.

Содержание:

* Заголовок "Баллы за неделю"
* Табличка/список вида:

  * Иван — 12
  * Маша — 9
  * Лёша — 3
    (сортировка по убыванию)

Дополнительно (внизу экрана, статический текст):

* "Баллы начисляются за выполненные задачи. Награды обсуждаются отдельно :)"

В первой версии не нужно:

* Тратить баллы
* Выбирать награды в приложении
* Историю за прошлые недели

## 2. Модели данных (основные сущности)

⚠ Важно: Формат задаётся так, чтобы его можно было хранить в Room (локальная БД), а потом синхронизировать между устройствами. Пока можно сделать только локально, без реальной синхронизации — это достаточно для MVP. Синхронка появится в v1.

### 2.1. FamilyMember

Член семьи.

```kotlin
data class FamilyMember(
    val id: String,            // UUID
    val displayName: String,   // "Иван", "Маша", "Папа"
    val roleLabel: String,     // "папа", "сын", "дочь" (чисто визуально)
    val avatarColor: String    // hex цвет для аватарки/бейджа
)
```

Примечание:

* пока аутентификации нет, мы считаем что текущий активный пользователь выбирается вручную (типа переключения профиля внутри приложения).
* в будущем → сделать нормальные аккаунты/сессии.

### 2.2. Task

Задача по дому.

```kotlin
data class Task(
    val id: String,                 // UUID
    val title: String,              // "Вынести мусор"
    val description: String?,       // "контейнер у дороги"
    val createdByUserId: String,    // кто назначил
    val assignedToUserId: String,   // кто должен сделать
    val dueDate: Long?,             // дедлайн (millis UTC) или null
    val repeatRule: RepeatRule,     // NONE / DAILY / WEEKLY
    val status: TaskStatus,         // TODO / DONE
    val createdAt: Long             // millis UTC
)
```

Вспомогательные enum'ы:

```kotlin
enum class RepeatRule {
    NONE,
    DAILY,
    WEEKLY
}

enum class TaskStatus {
    TODO,
    DONE
}
```

### 2.3. ShoppingItem

Пункт в списке покупок.

```kotlin
data class ShoppingItem(
    val id: String,               // UUID
    val title: String,            // "Молоко 2.5%"
    val createdByUserId: String,  // кто добавил
    val isBought: Boolean,        // куплено / не куплено
    val createdAt: Long           // millis UTC
)
```

### 2.4. FamilyEvent

Семейное событие (минимальная календарная штука).

```kotlin
data class FamilyEvent(
    val id: String,               // UUID
    val title: String,            // "Соревнования по бегу у Лёши"
    val date: Long,               // millis UTC (дата начала)
    val createdByUserId: String   // кто добавил
)
```

Для MVP нам не нужно время в часах-минутках, хватит просто даты (например, полночь указанного дня).

### 2.5. UserScore (баллы за неделю)

Хранит, сколько баллов набрал участник за определённую неделю.

```kotlin
data class UserScore(
    val userId: String,
    val weekStartDate: Long,  // millis UTC понедельника начала недели
    val score: Int
)
```

> Важно: мы считаем неделю с понедельника. weekStartDate — это "00:00 понедельника", в миллисекундах.

## 3. Логика приложения (бизнес-правила)

### 3.1. Создание задачи

* Любой участник может создать задачу.
* Он указывает, кому она назначена.
* После создания:

  * status = TODO
  * если есть repeatRule != NONE, то это считается повторяющейся задачей.

### 3.2. Выполнение задачи

* Если пользователь (или родитель за ребёнка) ставит задаче статус DONE:

  1. Исполнителю (`assignedToUserId`) начисляются баллы.

     * По умолчанию +1 балл за задачу.
  2. Если у задачи repeatRule == DAILY или WEEKLY:

     * она помечается DONE,
     * создаётся НОВАЯ такая же задача со статусом TODO и новой датой:

       * DAILY → dueDate = today+1 день
       * WEEKLY → dueDate = today+7 дней
     * createdAt у новой — сейчас.
     * Важно: новая задача должна иметь новый id.

То есть повторяемые задачи на самом деле "размножаются", а не "автоматически сбрасывают статус".

### 3.3. Баллы (UserScore)

* При каждом завершении задачи (Task.status меняется TODO → DONE):

  * определить текущую неделю (понедельник 00:00 этой недели).
  * найти в UserScore запись для (userId, этаНеделя).

    * если нет — создать со score = 1.
    * если есть — score++.

* Экран "Рейтинг" просто читает актуальную неделю и выводит всех FamilyMember + их score за эту неделю.

### 3.4. Покупки

* Любой может добавить позицию в список покупок.
* Любой может отметить "куплено".
* Покупка не даёт баллов.
* Покупка не удаляется автоматически после отметки "куплено", просто isBought = true. Удаление — вручную длительным тапом (или через иконку корзины).

Причина: часто покупают одно и то же снова через 2-3 дня, и удобно просто снять галку обратно.

### 3.5. События (FamilyEvent)

* Просто список событий, отсортированный по дате.
* На экране "Дом" показываем 1–2 ближайших событий с датой.
* Редактирование/удаление событий для MVP можно не делать, достаточно "добавить событие".

## 4. Хранение данных

### 4.1. Локально

Для MVP достаточно локальной БД через Room.
Создать DAO / Repository для:

* FamilyMember
* Task
* ShoppingItem
* FamilyEvent
* UserScore

### 4.2. Текущий активный пользователь

Нужно уметь переключать «я — это кто сейчас?».
Например, снизу/сверху в приложении маленький аватар текущего пользователя с выпадающим списком.

Это просто `currentUserId`, который хранится в DataStore (preferences).

```kotlin
data class AppSettings(
    val currentUserId: String
)
```

Для MVP аутентификации нет.
То есть все видят всё.
Приватности нет специально — она будет во второй версии.

## 5. Технические требования MVP

### 5.1. Технологии

* Kotlin
* Jetpack Compose
* Material 3
* ViewModel + StateFlow
* Room для хранения данных
* DataStore Preferences для currentUserId
* Navigation Compose для bottom nav

### 5.2. Минимальные компоненты

* BottomBar с 4 вкладками.
* По экрану на вкладку.
* Диалоги создания:

  * задачи,
  * покупки,
  * события.

### 5.3. Вёрстка

Стиль: чистый, спокойный, без "детского интерфейса", но не корпоративный.
Семейное ощущение, но без перегруза.

### 5.4. Локализация

Сразу делаем строки в `strings.xml`, язык — русский.
(Агент может сразу подготавливать под `R.string.*`.)

## 6. Что появится в v1 (после MVP, не делать сейчас)

Это сюда, чтобы агент знал направление архитектуры и не закладывал тупиковые решения:

* Приватные задачи / полупрозрачные задачи.
* Роли/права (дети не могут менять чужие задачи и баллы).
* Ротация обязанностей (кухня сегодня твоя / завтра его).
* Экран "Правила дома".
* Награды за баллы.
* Полноценный календарь (встречи с временем, кто должен прийти).
* Синхронизация между устройствами (например, через общий аккаунт семьи в Firebase).

## 7. Резюме для агента

1. Сделать Android-приложение на Kotlin + Compose + Room.
2. Реализовать 4 экрана: Дом, Задачи, Покупки, Рейтинг.
3. Добавить сущности: FamilyMember, Task, ShoppingItem, FamilyEvent, UserScore, AppSettings.
4. Сделать выбор текущего пользователя (currentUserId) и фильтрацию задач по нему.
5. Реализовать начисление баллов за выполненные задачи с учётом недели.
6. Реализовать повторяемые задачи через авто-создание новой копии при завершении.
7. Визуально — простой и читаемый Material 3.
