# Проверка производительности списка покупок

## Сценарии
1. **Пролистывание длинного списка** – 500 элементов, сгруппированных по категориям.
2. **Массовое добавление** – 30 последовательных добавлений через «Сохранить и добавить ещё».
3. **История действий** – загрузка 200 записей с подгрузкой следующей страницы.

## Наблюдения
- LazyColumn с разделителями и sticky-header удерживает рендер < 8 мс на кадр на Pixel 6 (API 34) при 500 элементах.
- Память на экране списка стабилизируется около 92 МБ, утечек не выявлено (LeakCanary, релизный build).
- История действий с лимитом 50 элементов за раз держит время запроса < 30 мс.

## Рекомендации
- При превышении 700 элементов включить server-driven пагинацию.
- Для экранов < 5" скрывать превью заметок, чтобы сократить высоту элементов.
- Продолжать профилирование после включения фоновой синхронизации истории.
